# Sci-PDF Enhanced 8.1.3.8（独立仓库维护版）

这是基于 https://github.com/syt2/zotero-scipdf 的非官方定制版本。
上游基线：b2831d6139f456b170100fe80195c8b588a1dd0f（main）。
保留原项目作者信息及 AGPL-3.0-or-later 许可，完整源码随包提供。
修改日期：2026-10-23。

## 本次新增

- 大尺寸多行网址框，默认高度 280px，支持垂直调整大小、横纵滚动、一行一个网址。
- 同时兼容旧版逗号、分号、空格分隔的列表；保存时去重、补全 `{doi}`。
- 支持手动保存，离开网址框也会保存；如存在格式错误则保留草稿和之前保存的列表。
- 可以填写一个地址来源页面，点击“立即获取并添加”，自动提取并合并地址。
- 可选启动时自动更新；每 24 小时最多请求一次，包括失败的尝试。Zotero 一直开启时不会定时轮询。
- 15 秒请求超时；失败不删除旧地址，不改变“自动下载 PDF”开关。
- 显示获取结果和最后成功获取时间；中英及繁体中文界面。

## 安装

1. 下载 `Sci-PDF-Enhanced-8.1.3.8.xpi`。无需解压 XPI。
2. Zotero → 工具 → 插件（或“插件管理器”）→ 右上角齿轮 → Install Add-on From File／从文件安装插件。
3. 先关闭所有 Zotero 设置窗口。选择 XPI 并接受安装提示，随后完全退出 Zotero，再重新启动。
4. 打开 Zotero 设置，在 Sci-PDF 页面查看新增控件。扩展管理器中显示为 Sci-PDF Enhanced。

本版本沿用原插件 ID（scipdf@ytshen.com），会替换原版，复用原来的网址设置，不能与原版并行启用。
8.1.3.8 起保留原插件 ID 和构建方式，更新地址改为 tom3410/zotero-scipdf-enhanced。旧安装包仍指向原仓库，需要手动安装一次新版才能切换更新来源；不要删除 manifest 的 update_url 字段。需要回到原版时，可从原项目手动安装。

## 使用

1. 地址框中每行填写一个完整的 http:// 或 https:// 网址；已有 `{doi}` 模板也可保留。
2. 在“地址来源页面 URL”中填写你使用的导航页或更新页完整链接。
3. 点击“立即获取并添加”。成功后自动合并保存；重复地址不会重复添加，手动地址保留。
4. 如果需要下次启动自动获取，勾选相应选项；此项默认关闭。

没有内置默认来源网站，因为需求中尚未指定。来源页可以带查询参数。
程序直接读取来源返回的 HTML：识别 `sci-hub.*`、`scihub.*` 主页链接及正文中的这类完整网址；
也接受链接文字标为 Sci-Hub 的其他域名主页。普通正文中不含 Sci-Hub 特征的任意域名不会被导入。
不会执行页面脚本；需要验证码、登录、JavaScript 渲染、跳转参数解析的网站需要额外适配。
本功能提取来源页所列地址，不验证地址是否最新、是否可用，也不保证来源准确。

## 8.1.3.4 手动验证测试版

这是需要实机确认的测试版，不代表已解决所有站点的下载限制。

- 保留 8.1.3.3 的地址输入框、来源更新功能与设置页结构。
- 修复跳转后相对 PDF 地址仍使用旧域名的问题。
- 遇到无法识别的网页或 HTTP 403/503，可打开 Zotero 自带网页窗口，允许手动验证、搜索 DOI、跟随页面跳转。
- 设置中的“下载受阻时打开窗口，手动验证后继续”默认启用。请使用条目右键菜单下面的“获取PDF”，上面的“查找全文”是 Zotero 自带功能。
- 完成验证并出现可识别 PDF 后自动保存。保存遇阻可点击“验证完成，重试保存”；跳过按钮换镜像；关闭窗口取消整批下载。窗口最多等待五分钟，每篇文章最多自动弹出一次。
- 文件下载使用 Zotero 的会话、网页来源和浏览器标识，并检查 PDF 文件头，避免把验证网页存成 PDF。外部 Chrome 的登录状态不会自动共享。
- 只能识别页面提供的 HTTP/HTTPS PDF 地址；blob 地址、复杂脚本阅读器或拒绝内置浏览器的网站仍可能失败。

验证范围：Node 单元测试、类型检查和安装包检查见配套验证记录。Linux Zotero 9.0.6 中设置页和关闭窗口取消测试通过；手动点击→Cookie→保存 PDF 的真实网页端到端测试未通过，原生查看器单独打开本地测试页也停在空白页。因此不能断言是插件问题，也不能断言只是测试环境问题，Windows 和实际 Sci-Hub 网站仍需实机确认。测试代码保留失败场景，不掩盖为通过。

## 8.1.3.5 成功后停止检索

- 正常下载继续使用 Zotero 原有附件导入方法；手动验证分支在需要时使用验证会话保存。
- 每篇文献按列表顺序尝试；PDF 保存成功后立即停止该篇剩余网址与 DOI 候选，批量任务继续下一篇。
- 仅检测到 PDF 链接不算成功，附件导入失败仍尝试下一镜像。
- 此停止逻辑在 8.1.3.4 代码中已存在，本版为用户指定的三种行为添加回归测试，未新增可能误关的设置开关。
- 手动验证仍为测试功能，真实网页的完整保存流程尚未验证通过。可在设置取消勾选手动窗口选项，保留普通下载。

## 8.1.3.6 验证后自动挂载附件

针对用户反馈：验证完成、页面显示 PDF 时弹出另存为，最终文件在下载目录，条目没有附件。

- 在验证页面导航前安装窗口专用的 PDF 响应接管。包括顶层页面及其内部框架、直接 PDF 和返回下载附件的 PDF。
- 接收该响应的真实 PDF 字节，再调用 Zotero 的附件导入接口，明确指定发起下载的条目 ID 和库 ID；无需再为同一文件发起一次 HTTP 请求或选择另存为路径。
- 只处理当前验证窗口及内部框架的 PDF。其他 Zotero 窗口、后台 HTTP 请求、HTML 验证页和普通非 PDF 下载不受影响。
- 保存成功关闭验证窗口，并停止当前文章剩余镜像。已收取 PDF 但导入失败时，点击重试会复用收到的文件；响应中断时重试会重新请求该地址。取消或关闭窗口清理监听和进行中的接收。
- 正常无需验证的下载入口与导入方式保持原样。

验证：47 项 Node 单元测试、类型检查、生产构建与 XPI 检查。Linux Zotero 9.0.6 的两项原生测试通过：真实 HTTP 的 Content-Disposition 附件响应接管、实际 PDF 子附件导入（含父条目、库、文件存在验证）；独立 HTTP 下载不被接管。

原生测试使用本地模拟 PDF，针对流接管测试以精确本地 URL 限定请求范围；真实浏览器上下文范围的匹配另有单元测试。未在 Windows 上重现真实网站的人机验证→PDF 响应完整流程，不能将以上测试等同于该流程已实测成功。用户已确认 8.1.3.5 可打开验证并到达 PDF，本版修复后续保存衔接。

## 8.1.3.7 Windows 保存路径修复

用户截图报错 `could not parse path (NS_ERROR_FILE_UNRECOGNIZED_PATH)`，出错路径形如 `D:\zotero文献\storage\tmp-xxx/article.pdf`。
原因是 8.1.3.6 用字符串加 `/article.pdf`，混入 Windows 路径。现改用 `nsIFile.clone()` 与 `append("article.pdf")` 构建系统路径，同一个路径用于文件写入和附件导入，保留中文目录。

新增含中文 Windows 存储目录的回归测试，并调整失败提示，不再将本地写文件失败一概提示为需要验证。
安装后完全退出 Zotero 并重新启动，再获取原文献。无需修改数据目录、系统权限或重新配置网址列表。
